# Forma Parts: план інтеграції

## Що вже є

PremierParts використовує Django ORM і Django migrations (не SQLAlchemy/Alembic). Каталог уже має `Category`, `Product`, `Manufacturer`, `Make`, `CarModel`, `Generation`, `Fitment`, `ProductImage`. Фото зберігаються в `MEDIA_ROOT` на сервері; `ProductImage.source_url` дозволяє уникати повторного завантаження. Поточний каталог містить товари з імпорту старого сайту, тому Forma ID не можна записувати в поля `legacy_id` / `legacy_url`. `Product.sku` не має унікального обмеження. Окремих фонових задач і scheduler немає.

## Модель даних

- Використати наявні категорії, товари, марки, моделі, покоління та `Fitment` для сайту.
- Додати окремі таблиці зв'язку Forma category ID → `Category`, Forma `itemNo` → `Product`, Forma `typeId`/fallback → `Generation`; зберігати оригінальні JSON-відповіді та час останнього спостереження.
- Додати нормалізовані назви характеристик, значення характеристик товарів та складські залишки. Для Forma fitment зберігати окремий source-зв'язок і створювати існуючий `Fitment` для пошуку на сайті.
- Додати запис запуску синхронізації зі статусом, лічильниками й помилками.

## Синхронізація

1. `FormaClient` із токеном з environment, timeout, обмеженими retry для 429/5xx, обробкою 401 та керованою паралельністю. Відомі POST `https://ecom.ad.ua/api/content/Catalog` (дерево; метод підтверджено відповіддю `Allow: POST`), POST `https://ecom.ad.ua/api/items/ByTreeId` (тіло — JSON number) і POST `https://ecom.ad.ua/api/Catalog/ItemVehicles` (тіло — JSON string).
2. FULL: рекурсивно обійти дерево, оновити категорії, для листків отримати товари, характеристики, залишки, фото та сумісність. Обробляти пакетами, продовжувати після помилки окремого товару, нічого не видаляти жорстко.
3. FAST: за збереженими leaf category ID оновити ціни та залишки без повторного запиту фото/авто.
4. Фото завантажувати у `MEDIA_ROOT` лише після підтвердження base URL. Використовувати стабільний шлях/`source_url`, перевіряти тип і розмір, повторний sync не має дублювати файли.
5. Запуск із management command; admin створює job, окремий worker виконує його поза HTTP-запитом. Періодичні FULL/FAST запуски через окремий worker лише після налаштування credentials.

## Мапінг і обережні правила

- Ідентифікатор товару Forma: `itemNo` у власній таблиці; існуючий `Product` пов'язувати лише за однозначним нормалізованим артикулом і брендом.
- `retail` можна застосовувати як роздрібну ціну, якщо значення коректне. `price` зберігати як окрему ціну Forma без припущення, що це закупівельна ціна; не записувати її в існуюче `Product.supplier_price` без підтвердження семантики.
- Наявність визначати за розібраним `stock` (включно з `Q=">3"`) та `inStock`; не покладатися лише на `quantity`.
- `typeName` зберігати як назву типу, не перетворювати `06-13` на роки без підтвердження.
- Для глибокого дерева категорій поправити підрахунок товарів у всіх предків.

## Непідтверджені деталі Forma

Отримано приклад відповіді POST дерева: масив із рекурсивними `childElements`, `sort` та відносним `img`. Підтверджено base URL фото товарів `https://img2.ad.ua/imgs/` та категорій `https://img2.ad.ua/imgs/group-pic/`: обидва приклади повертають JPEG із HTTP 200. Потрібні приклад тіла запиту дерева (або підтвердження, що воно порожнє); за можливості login/refresh endpoint та endpoint додаткових фото. Секрети вводяться лише через `.env`/secret storage, не в HAR і не в Git.

## Перевірка

Тести з моками для дерева, нормалізації, stock JSON і `>3`, характеристик, авто з порожніми полями, повторних синхронізацій, помилок API й фото. Після отримання доступу — тестовий FULL/FAST запуск на малому наборі категорій, потім перегляд результату в адмінці та API сайту.
